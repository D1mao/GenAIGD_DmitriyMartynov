## Шаг 1. Img2img test

**Контекст:**
- Какой кадр взят: `01-w06-hero-base.png` (базовый Криворукий Крыс, нейтральная поза)
- Что в нём уже работало: уши, цвет кожи, жилет с заплатой, общий пиксар-стайл
- Что нужно было исправить: искажённые пальцы левой руки, слишком яркий блик на лбу, нечитаемая форма босых ступней

**Что фиксировали:**
- Модель: `sd_xl_base_1.0.safetensors` (SDXL)
- Workflow: `workflows/w07_img2img_inpaint_outpaint.json`
- Seed: 1000 (фиксирован для всех прогонов)
- Основные параметры: steps=25, cfg=7, sampler=euler, scheduler=simple, size=1024×1024

**Что меняли:**
- Denoise: тестировали 0.4, 0.6, 0.8

**Вывод:**
- Что принимаем: denoise = 0.6 (пальцы выровнялись, блик исчез, ступни появились, стиль сохранился)

# HW08 — ControlNet Depth / Canny для локаций

### Цель
- Какие будущие скрингены я готовлю: «вертикальная пещера для механики передачи сундука» и «вход в логово дракона для установочного плана».
- Что хочу контролировать: глубину ярусов (Depth) и контуры скал/дракона (Canny).
- Почему выбрал Depth / Canny: Depth нужен для многоплановой вертикальной сцены, Canny — для чёткой формы входа и дракона.

### Использованный workflow
- Tool: ComfyUI Cloud
- Workflow: `w08_depth.json` и `w08_canny.json`
- Model: `sd_xl_base_1.0.safetensors`
- Control mode: Depth (Depth Anything) / Canny (Canny edge)
- Input image / sketch / reference: для Depth — нарисованный от руки скетж трёх ярусов; для Canny — контурный рисунок входа.

### Результаты

На данный момент ComfyCloudUi не позволяет генерировать изображения в workflow бесплатным пользователям даже при наличие credits.

### Вывод
- Depth отлично подходит для вертикальных пещер — он сохраняет ярусность и перспективу, стиль почти не страдает. Это идеально для нашей механики.
- Canny полезен для входа в логово: дракон и скалы узнаваемы, но с весом выше 0.7 убивает пиксар‑стилизацию.
- Оба подхода можно использовать для финальных локаций. Нужно аккуратно настраивать пороги Canny, чтобы избежать шума.
- Следующий шаг: добавить гоблинов в эти локации через inpaint или IP-Adapter.

- **IP-Adapter** – главный кандидат для переноса стиля с наших референсов (например, текстура грибов, палитра из «Тайны Коко»). Но сейчас нет доступа к нужному workflow.
- **Flux 2 / Klein** – избыточны для текущего этапа; проект находится на уровне генерации концепт‑артов, а не производственного пайплайна.
- **Simple upscale** – будет использован сразу для двух лучших изображений локаций, которые я отобрал ранее. Это повысит их качество для GDD.

Ближайшие действия: дождаться доступа к серверу или настроить локальный ComfyUI, чтобы протестировать IP-Adapter на входных референсах.
